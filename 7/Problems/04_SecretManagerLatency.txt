The "Secrets Manager Latency & API Throttling" problem occurs because retrieving encrypted credentials from a cloud vault over the network is computationally heavy and strictly rate-limited by the cloud provider.


What Would Have Happened If Ignored
In a basic architecture, every time OPENEMR_POST_LAMBDA or FITBIT_FETCHER_LAMBDA executes, it makes a standard AWS SDK call to AWS Secrets Manager (GetSecretValue). Secrets Manager then calls AWS KMS to decrypt the Customer-Managed Key (CMK) before sending the token back over the network to the Lambda.

 * The Latency Tax: This round-trip network and cryptographic decryption process adds roughly 50\text{ ms} - 150\text{ ms} of latency to every single Lambda execution.

 * The Cost Explosion: AWS charges for every 10,000 API calls to Secrets Manager and KMS. If OmniHealth processes 10 million bedside monitor alerts (Task 3) a month, you are burning hundreds of dollars just repeatedly asking for the exact same Hospital A OAuth token.

 * The Catastrophic Bottleneck (Throttling): AWS Secrets Manager has a hard regional API quota (e.g., 10,000 requests per second). If Hospital A does a massive data sync and triggers 15,000 Lambdas simultaneously, AWS Secrets Manager throws a ThrottlingException (HTTP 400 Rate Exceeded). Your integration pipeline completely crashes, not because the hospital failed, but because your own Lambdas accidentally DDoS-attacked your own cloud vault.


How We Solved It (Architecture Integration)
We eliminated the network bottleneck by implementing In-Memory TTL Caching using the official AWS Parameters and Secrets Lambda Extension.

 * The Local Proxy (The Lambda Extension)
   * Instead of writing custom caching code, we attached the AWS-provided Extension Layer to all our backend Lambdas.
   * This extension boots up a lightweight, local HTTP server (http://localhost:2773) inside the Lambda's secure execution environment.

 * The Cache Miss (Cold Start)
   * When the Lambda needs Hospital A’s OIDC tokens, it does not call the AWS network. It queries localhost:2773.
   * If the local cache is empty, the extension reaches out to AWS Secrets Manager, decrypts the token via KMS, and hands it to the Lambda code.
   * Crucially, the extension saves that decrypted token in the Lambda container's secure, volatile RAM with a Time-To-Live (TTL) of 300 seconds (5 minutes).

 * The Cache Hit (Subsequent 1,000 Executions)
   * Because Lambda containers are reused for subsequent events ("warm starts"), the next 1,000 bedside monitor events processed by that specific container query localhost:2773 and instantly receive the token directly from local RAM.
   * The retrieval time drops from 100\text{ ms} to < 5\text{ ms}.
   * Zero network calls are made to AWS Secrets Manager. Zero KMS decryption costs are incurred.


 * Proactive Invalidation
   * If Hospital A's server returns a 401 Unauthorized (meaning the token expired early), the Lambda code gracefully catches it, commands the local extension to flush the cache, executes the token refresh flow, and repopulates the local cache with the new token.


Advantages
 * Sub-Millisecond Speed: You shave massive amounts of latency off every API call and data transfer, making real-time mobile syncs (Tasks 2.1 and 13) feel instantly responsive to the end-user.
 * Immunity to API Quotas: Because 99% of requests are served from local RAM, you can scale to millions of concurrent executions without ever triggering an AWS Secrets Manager throttling limit.
 * Drastic Cost Reduction: You reduce your Secrets Manager and KMS billing footprint by up to 99%, turning a major architectural bottleneck into a hyper-efficient edge cache.

### Step 4: AWS Lambda Code (Localhost Proxy Retrieval)

Now we write the Python code. Instead of using `boto3` to make a slow, expensive network call to AWS Secrets Manager, we use the standard `requests` library to make a lightning-fast call to the local extension server running on `localhost:2773`.

```python
import os
import json
import requests

# The exact name of the secret stored in AWS Secrets Manager
SECRET_NAME = "omnihealth/hospital-b/credentials"

# The local proxy endpoint spun up by the AWS Lambda Extension
# Notice this is HTTP, not HTTPS, because the traffic never leaves the container's RAM
LOCAL_EXTENSION_ENDPOINT = f"http://localhost:2773/secretsmanager/get?secretId={SECRET_NAME}"

def lambda_handler(event, context):
    try:
        # 1. Fetch credentials from the local in-memory cache
        # The AWS_SESSION_TOKEN is required for security to prove this call 
        # is coming from the authorized Lambda container itself.
        headers = {"X-Aws-Parameters-Secrets-Token": os.environ.get('AWS_SESSION_TOKEN')}
        
        # This request takes < 5ms if cached. It takes ~100ms on a cold start.
        cache_response = requests.get(LOCAL_EXTENSION_ENDPOINT, headers=headers)
        
        if cache_response.status_code != 200:
            raise Exception(f"Failed to retrieve secrets from cache: {cache_response.text}")
            
        # 2. Parse the secret payload
        secret_string = cache_response.json()['SecretString']
        credentials = json.loads(secret_string)
        bearer_token = credentials.get('hospital_b_api_key')
        
        # 3. Simulate transmitting data to the external hospital
        hospital_url = "https://emr.hospital-b.com/fhir/Bundle"
        
        api_response = requests.post(
            hospital_url, 
            json={"resourceType": "Bundle"}, 
            headers={'Authorization': f'Bearer {bearer_token}'},
            timeout=5
        )
        
        # 4. Proactive Cache Invalidation
        if api_response.status_code == 401:
            print("Token expired. In a real scenario, trigger OIDC refresh flow here.")
            # Because the secret changed, you must wait for the 300s TTL to expire,
            # or force the extension to flush by overriding the TTL header on the next GET request.
            raise Exception("Unauthorized: Invalid Bearer Token")
            
        return {"status": 200, "message": "Success"}

    except Exception as e:
        print(f"Execution failed: {str(e)}")
        raise e

```
